# Design Context

## Users
Internal engineers and knowledge owners at enterprises using the MCP server — developers, SREs, tech leads,
and knowledge managers. They open the file manager during the workday, often alongside an IDE and a terminal,
to drop SOPs, runbooks, PDFs, and exports into the knowledge base. They are technical, fast, impatient with
decoration, and reuse keyboard shortcuts. The job: get documents in and organized so retrieval (RAG) and
actions (tools) work on them minutes later.

## Brand Personality
**Grounded. Precise. Unimpressed.** This is an enterprise tool that earns trust by feeling solid and
predictable, not by performing. It sits next to Postgres, Prometheus, and the IDE — it should feel like it
belongs there. Calm, dense, tool-like. No delight for its own sake; the delight is that it does exactly what
it says, quickly, and stays out of the way.

## Aesthetic Direction
**Refined utilitarian, dark.** Think the best parts of Linear, GitHub, and Notion's dark theme — confident
neutrals, sharp typography, deliberate density, and a single restrained accent. Surfaces are flat; hierarchy
comes from type weight, spacing, and subtle value shifts — never from drop shadows, glows, or gradients.

- **Theme:** dark only (for now). Single, polished theme.
- **Accent:** a refined warm amber (`oklch`) — chosen because it reads as "knowledge/archive" rather than
  "AI cyan/purple," and it stays legible against dark neutrals without glowing. Used sparingly: active states,
  focus rings, primary actions, selection. Everything else is neutral.
- **Neutrals:** tinted faintly toward the accent hue for cohesion (chroma ~0.005–0.01). No pure black/white.
- **Typography:** a distinctive sans for UI body + a refined monospace for paths, IDs, counts, and metadata
  (the things an engineer's eye scans for). Avoid the reflex font list (Inter, Geist, IBM Plex, Space
  Grotesk, etc.) — pick something with character that still reads as a tool, not a marketing site.
- **Density:** app-grade fixed `rem` scale (no fluid type). Tight, scannable rows. No marketing spacing.

### Anti-references (explicitly avoid)
- **Generic AI slop:** cyan-on-dark, purple-to-blue gradients, glassmorphism, side-stripe accent borders
  (`border-left: 3px solid`), rounded-rect cards with drop shadows, gradient text, glow effects, sparklines
  as decoration, modals for things that could be inline.
- **SharePoint's look:** we are "SharePoint-like" in *function* only (folders, upload, versioning,
  permissions). Avoid its cluttered chrome, dated gradients, ribbon toolbars, and corporate-blue palette.
- **Decorative maximalism:** no animation theater, no bouncy easings, no parallax. Motion only conveys state
  change (entrance, feedback) with smooth exponential deceleration.

## Design Principles
1. **Density over padding.** An engineer should see their file tree, the current folder's contents, and
   metadata without scrolling. Whitespace is structural, not decorative.
2. **Type does the hierarchy.** Weight, size, and mono-vs-sans carry the structure. Borders and backgrounds
   are secondary, used only to separate regions.
3. **One accent, used like punctuation.** Amber marks the active path, the focused input, the primary
   action. If everything is amber, nothing is.
4. **Flat and honest.** No fake depth. Surfaces are flat values; "elevation" is a slightly lighter neutral,
   not a shadow. Selection is a tint, not a glow.
5. **Keyboard-first, mouse-complete.** Every list row, folder, and action is reachable and operable from the
   keyboard. Focus states are obvious. Drag-and-drop is a power-up, not the only way.
6. **Calm under load.** Loading is a quiet skeleton or inline indicator — never a full-screen spinner overlay.
   Errors are specific, inline, and actionable.

## Implementation Notes
- **Stack:** React + TypeScript (Vite), built to static assets and served from the Spring Boot JAR's
  static resources — no separate web server (native-only constraint in `docs/`).
- **Scope now:** Web UI slice 1, Files & Folders surface only (`docs/plan.md` Phase 2 deliverable, pulled
  forward so the UI is exercisable early). Universal search and connectors console come later.
- **Icons:** a single, restrained icon set (e.g. Lucide) at consistent sizes. No emoji as UI.
- **Spacing scale:** 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64. Semantic tokens (`--space-sm`, etc.).
- **Radius:** small and consistent (e.g. 6px for controls, 8px for panels). No big pill rounding.
